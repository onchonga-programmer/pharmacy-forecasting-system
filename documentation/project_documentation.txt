1. PROJECT OVERVIEW
================================================================================

This project builds a machine-learning-based demand forecasting system for
pharmacy sales data. The goal is to predict weekly drug sales quantities across
8 drug categories (identified by ATC codes), and to evaluate how well a trained
model generalises to future, unseen time periods.

The system implements and compares three classes of forecasting models:
  - Statistical baseline models (Naive, Seasonal Naive, SES, MA-4, WMA-4,
    Holt-Winters)
  - SARIMA (Seasonal AutoRegressive Integrated Moving Average)
  - XGBoost (gradient-boosted decision trees with engineered time-series
    features)

The final pipeline follows a strict 3-way temporal split:
  - TRAINING    : 2014 – 2017  (model learns from historical patterns)
  - VALIDATION  : 2018         (hyperparameter tuning and model selection)
  - FINAL TEST  : 2019         (out-of-sample generalisation test)

This design ensures no data leakage and provides an academically rigorous
evaluation of real-world model performance.

6. FEATURE ENGINEERING
================================================================================

Notebook: notebooks/pharmacy_sales_feature_engineering.ipynb

This notebook transforms the cleaned time-series data into a supervised machine
learning dataset with 47+ engineered features per observation.

Features created:

  TIME FEATURES:
    - month, quarter, week_of_year
    - month_sin, month_cos        — cyclical encoding for month
    - quarter_sin, quarter_cos    — cyclical encoding for quarter
    - week_sin, week_cos          — cyclical encoding for week of year
    - time_index                  — cumulative week count across all history
                                    (NOT reset per drug; counts from data start)

  LAG FEATURES (previous sales values):
    - lag_1   — previous week
    - lag_2   — 2 weeks ago
    - lag_4   — 1 month ago
    - lag_13  — 1 quarter ago
    - lag_52  — same week last year

  ROLLING WINDOW STATISTICS (computed per drug, no data leakage):
    Windows: 4, 13, 26, 52 weeks
    - rolling_mean_{w}
    - rolling_std_{w}
    - rolling_min_{w}
    - rolling_max_{w}

  EXPONENTIALLY WEIGHTED MOVING AVERAGES (EWM):
    - ewm_mean_4, ewm_mean_13, ewm_mean_26

  EXPANDING STATISTICS (computed using only historical data up to each point):
    - expanding_mean   — running mean of all past values
    - expanding_std    — running standard deviation
    Note: These are calculated using ALL available history (2014 onwards),
          ensuring no future leakage when applied in the 2019 test set.

  DRUG-LEVEL ENCODING:
    - drug_encoded     — integer label encoding of drug_name (sorted
                         alphabetically for reproducibility)
    - atc_main_group   — ATC main group encoding:
                           M (Musculo-skeletal) → 0
                           N (Nervous system)   → 1
                           R (Respiratory)      → 2
                         Note: Uses FIRST CHARACTER of ATC code, NOT full code

  DRUG STATISTICS (per-drug summary values from full training history):
    - drug_mean, drug_std, drug_min, drug_max, drug_cv

Data Split Applied in This Notebook:
  - All data up to 2017-12-31   → train sets  (train_xgboost.csv, etc.)
  - All data from 2018-01-01    → test sets   (test_xgboost.csv, etc.)
  - A label_encoders.pkl file is saved for reproducing encodings

Output files:

  - data/processed/test_sarima.csv
  - data/processed/train_baseline.csv

7. TEMPORAL TRAIN / VALIDATE / TEST SPLIT STRATEGY
================================================================================

  ┌────────────────────────────────────────────────────────────────┐
  │  PERIOD         │  YEARS     │  PURPOSE                       │
  ├─────────────────┼────────────┼────────────────────────────────┤
  │  Training Set   │ 2014–2017  │ Model learns demand patterns   │
  │  Validation Set │ 2018       │ Hyperparameter tuning, metrics │
  │  Test Set       │ 2019       │ Final out-of-sample evaluation │
  └─────────────────┴────────────┴────────────────────────────────┘

Rationale:
  - Temporal splits are mandatory for time-series data to prevent data leakage
  - Using full calendar years (instead of random splits or rolling windows)
    ensures each split captures complete seasonal cycles
  - The 2019 test set is unseen during training AND validation — providing a
    true measure of real-world generalisation
  - 5 full years of training data is sufficient to learn weekly, monthly, and
    annual seasonal patterns
  - 2019 data is partial (Jan–Oct) but this is acceptable since all 4 seasons
    are represented across the full training history

This 3-way split applies to ALL models: baseline, SARIMA, and XGBoost.

Purpose:
  To evaluate the trained XGBoost model (trained on 2014-2017, validated on
  2018) against completely unseen 2019 data. This is the final, definitive

  1. The 2019 weekly sales data is loaded and feature-engineered using the

  - Loaded from: data/results/xgboost/validation_2018_metrics.json

================================================================================
13. MODEL DRIFT ANALYSIS
================================================================================

The XGBoost model shows significant performance degradation from 2018 to 2019.

Primary Driver: N02BE — Feature Engineering Pipeline Mismatch (Bug 7)
  - 2018 MAE: 0.17  (appeared near-perfect — this was an ARTEFACT)
  - 2019 MAE: 121.39 (catastrophic failure)

  ROOT CAUSE (confirmed by debugging in model_validation_2019.ipynb):
  The data cleaning pipeline (data_cleaning.ipynb) applied winsorization
  (outlier capping) to raw sales quantities. For N02BE, this capped all
  values at 99.625 units/week.

  Evidence:
    - train_xgboost.csv N02BE range : 92.0 – 99.625  (all capped)
    - test_xgboost.csv  N02BE range : 99.625 – 99.625 (constant — ALL rows)
    - Database raw 2019 N02BE range : 86 – 546

  The 2018 "validation" had N02BE as a constant series (all = 99.625).
  The model predicted ≈ 99.625 for every row → MAE = 0.17 was trivially
  achieved by predicting the constant. R² = 0.000 confirms this: there
  was no variance to explain.

  In 2019, the validation notebook queried raw uncapped database values
  and used them directly to compute lag features (lag_1 = 289, lag_52 = 255).
  These values are completely out-of-distribution for a model trained on
  capped data (where lag features were always ≤ 99.625). The model predicted
  ≈ 71 when the actual was ≈ 354 → MAE = 121.39.

  This is a FEATURE ENGINEERING PIPELINE MISMATCH, not concept drift.
  The 2019 actual N02BE mean is 193, which is lower than the historical
  mean of 208 — so demand did NOT surge; the pipeline simply forgot to
  apply the same cap that was present during training.

  Fix applied (model_validation_2019.ipynb, debug cell):
    1. Learn per-drug caps from train_xgboost.csv (e.g., N02BE cap = 99.625)
    2. Cap df_full (2014–2019 history) before computing lag/rolling features
    3. Cap df_2019 actuals for a fair apples-to-apples comparison
    4. Rebuild all lag/rolling features using capped history
    5. Re-run predictions with corrected features

Other Drug Degradation (moderate, genuine drift):
  - M01AB (+303.6%), M01AE (+307.1%), N02BA (+75.3%), N05B (+97.4%),
    R06 (+394.1%), R03 (+79.1%) all show moderate degradation
  - These are consistent with real distributional shift over 2+ years
    (model trained to 2017, tested in 2019)
  - None have the extreme factor seen in N02BE

Stable Drugs (model remained reliable):
  - N05C : MAE improved from 0.98 to 0.80 (-18.4%) ← Very stable demand
  - R06  : MAE increased only +7.5%               ← Seasonal pattern stable

Interpretation for Thesis:
  The XGBoost model achieved R²=0.9913 on the 2018 held-out validation set,
  demonstrating strong in-distribution predictive performance. The 2019
  out-of-sample test revealed two distinct failure modes:

  (a) Pipeline inconsistency (N02BE): The outlier capping applied during
      data cleaning was not reproduced during 2019 inference, causing
      lag features to be orders of magnitude outside the model's training
      distribution. This highlights the critical importance of encapsulating
      all preprocessing steps in a reproducible inference pipeline.

  (b) Genuine temporal drift (remaining 6 drugs): Moderate degradation
      (+75–394%) reflects real changes in demand patterns over the
      2018-2019 period and demonstrates the need for periodic retraining
      in production pharmacy forecasting systems.

Recommendations:
  1. Fix inference pipeline: apply identical outlier caps (from training
     data) to all lag/rolling features before scoring new data
  2. Retrain model annually with the most recent 4 years of data
  3. Implement drift detection: alert if rolling 4-week MAE exceeds
     1.20 × the 2018 per-drug baseline
  4. Consider retraining on uncapped data so the model can handle the
     full demand range for high-volume drugs (N02BE, N05B)

14. BUGS FOUND & FIXED DURING DEVELOPMENT
================================================================================

The following technical issues were identified and resolved during development:

  Bug 1: Feature Column Order Mismatch
    - Problem : XGBoost model expected features in a specific column order.
                Running model_validation_2019.ipynb produced a
                "feature_names mismatch" error.
    - Fix     : Reordered the 2019 feature DataFrame to match the exact
                column sequence used during model training using
                feature_cols_ordered.

  Bug 2: time_index Computed Incorrectly in 2019 Notebook
    - Problem : time_index was computed as range(len(df_2019)), which reset
                the counter to 0 for 2019. The model expected a cumulative
                index counting from 2014.
    - Fix     : Changed to compute time_index as cumulative week count from
                the start of the full dataset (2014 onwards).

  Bug 3: Expanding Stats Computed Only on 2019 Data
    - Problem : expanding_mean and expanding_std were calculated using only
                the 2019 slice of data. This gave wrong values and was a
                form of data inconsistency.
    - Fix     : Recalculated expanding stats using the full 2014-2019 history
                concatenated, then selected 2019 rows after computation.

  Bug 4: ATC Encoding Used Full Codes Instead of Main Group
    - Problem : During 2019 re-encoding, the full ATC code (e.g., 'M01AB')
                was mapped instead of the main group initial character ('M').
                This caused the model to receive encoding values it had never
                seen during training.
    - Fix     : Applied .str[0] to extract the first character of the ATC
                code before mapping to the integer encoding (M→0, N→1, R→2).

  Bug 5: Drug Label Encoding Not Reproducible
    - Problem : Drug integer encoding used an unsorted list of drug names,
                meaning the mapping could vary between runs depending on the
                order data appeared.
    - Fix     : Enforced sorted(df['drug_name'].unique()) to ensure the
                encoding is always alphabetically consistent.

  Bug 6: Hardcoded 2018 Benchmark Values Became Stale
    - Problem : model_validation_2019.ipynb had hardcoded 2018 metrics
                (MAE=1.40, per-drug MAEs) from an earlier training run.
                After retraining on 2014-2017, the actual 2018 results
                changed to MAE=1.81 — making all comparisons incorrect.
    - Fix     : Replaced all hardcoded values with dynamic loading from:
                  - validation_2018_metrics.json  (overall metrics)
                  - xgboost_results.csv           (per-drug metrics)
                All thresholds (e.g., MAE < 2.17) are now computed at
                runtime as mae_2018 × 1.20.

  Bug 7: Training Outlier Cap Not Applied to 2019 Inference Pipeline
    - Problem : The data cleaning pipeline winsorized (capped) sales
                quantities per drug to remove outliers before training.
                For N02BE, this cap was 99.625 units/week. In the 2018
                test split, ALL N02BE values were exactly 99.625 (constant).
                The model learned to predict ≈ 99.625 for N02BE — giving
                an artefactual MAE of 0.17 (near-zero error on a constant).

                In model_validation_2019.ipynb, the 2019 data was loaded
                directly from the database (raw, uncapped values up to 546)
                and lag features were computed from this raw history
                (lag_1 = 289 instead of ≤ 99.625). These values were
                completely out-of-distribution for the trained model,
                causing predictions of ≈ 71 against actuals of ≈ 354,
                producing MAE = 121.39.

    - Confirmed by:
                  • train_xgboost.csv N02BE range: 92.0 – 99.625
                  • test_xgboost.csv  N02BE range: 99.625 – 99.625 (constant)
                  • Database 2019 N02BE range    : 86 – 546 (raw)
                  • Encoding sensitivity test: prediction unchanged across
                    all drug_name_encoded values (0–7) → encoding not the cause
                  • lag_1 mismatch confirmed: stored 289.0, expected ≤ 99.625

    - Fix     : In model_validation_2019.ipynb (debug section):
                  1. Learn per-drug caps from train_xgboost.csv
                  2. Apply caps to df_full before computing lag/rolling features
                  3. Apply caps to df_2019 actuals for fair comparison
                  4. Rebuild all lag/rolling/EWM features from capped history
                  5. Re-score with corrected feature matrix

    - Lesson  : Any preprocessing step applied during training (scaling,
                capping, encoding) MUST be reproduced identically during
                inference. Saving the cap values alongside the model
                (e.g., in a preprocessing_config.json) is recommended
                for all future pipelines.

17. KEY CONCLUSIONS
================================================================================

1. XGBoost Outperforms All Baselines on 2018 Validation
   XGBoost achieved MAE=1.81 vs the best baseline (Holt-Winters) at MAE=6.91
   — a 74% improvement. R²=0.9913 confirms the model captured nearly all
   variance in the 2018 data. XGBoost also significantly outperformed SARIMA
   (4/8 drugs beat baseline) across all volume segments.

2. 2019 Validation Revealed Pipeline Bug and Genuine Drift
   The 2019 out-of-sample test showed +932% overall MAE degradation. Debugging
   revealed TWO distinct causes:
   (a) Pipeline bug (N02BE): Training data was winsorized at 99.625/week but
       the inference notebook used raw uncapped values — lag features were
       completely out-of-distribution for the trained model.
   (b) Genuine temporal drift (6 other drugs): +75–394% degradation over the
       2018–2019 period, consistent with real demand shifts.

3. N02BE 2018 "Perfect" Score Was an Artefact
   The reported MAE=0.17 for N02BE in 2018 was not real model skill — the
   entire 2018 test split for N02BE was a constant value (99.625), making
   trivial prediction possible. R²=0.000 confirmed zero explainable variance.
   The true 2018 model skill for N02BE cannot be assessed from capped data.

4. Model Needs Periodic Retraining
   The 2019 results demonstrate the necessity of a model monitoring and
   retraining pipeline in any production deployment. The model should be
   retrained at minimum annually, with drift alerts if weekly residuals
   exceed 20% of the 2018 baseline.

5. Feature Engineering Proved Critical
   The rich feature set (lags, rolling stats, cyclical encodings, expanding
   stats) was key to XGBoost's strong 2018 performance. Simpler models
   (SARIMA, Holt-Winters) could not match this level of accuracy.

6. Temporal Validation is Essential for Time-Series Models
   Using a strict temporal split (no random shuffling) and an independent
   final test year prevented overfitting and produced honest, reportable
   results suitable for academic publication.
